# False-positive review + `ws-etw-0` retrain on all DC-era data (2026-11-15)

User ask: check every live false positive; the model looked like it had never seen some benign behaviour, so retrain on all
data from the start, and deploy if the new model is better. Plan: `~/.claude/plans/i-need-to-check-wondrous-chipmunk.md`.
Outcome: **`exp17-ws0` live on `ws-etw-0` since 2026-11-15 ~13:43Z** (user decision, despite the attack-score drop below).
The `ws-etw-1` retrain was **aborted by the user** ("it does not have false positives like ws0"), so `ws-etw-1` stays on `exp15-ws1`.

## Method

- **Same windows, both models.** Every saved live window since 11-12 16:05Z (`src/live/sessions/live-*-<host>*/windows/<wid>/edges.csv`,
  latest session copy per window) was re-scored with `score_window.score_edges` + `alg1.construct` at the live settings (Moderate
  from 4.5, NET rule off). The script lives in the session scratchpad and on the trainer (`~/retrain-20261115/rescore_sessions.py`, not in the repo).
  Check: the old model's re-score reproduced the live scores (17.30, 7.49, 4.60, 52.65, 19.86, 7.24).
- **Window categories** come from the exclusion file labels (`attack` / `ours` / `canary`; else benign). Benign windows are split into
  *train* (in exp17's training data), *val* (its held-out last 60 windows, 09:20–11:20Z) and *fresh* (after the range end 11:20Z).
- **Label source:** my reading of Loki ProcessStart (kproc), Sysmon EID 1 command lines and kfile, plus the LLM verdict, and the user's
  confirmation for the ws-etw-1 05:55Z window. No oracle (D6), so no P/R/F1.
